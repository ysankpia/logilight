# 产品规划：一个轻量的罗技鼠标控制工具

目标是把现在分散在三处的三件事收进一个产品，而不是把三份代码拼在一起：

| 能力     | 现状                            | 归属                                |
| -------- | ------------------------------- | ----------------------------------- |
| 定时灯光 | LogiLight（本仓库）             | 保留                                |
| DPI      | OpenLogi（22 万行，3 个进程）   | 只取设备层能力，之后可卸载 OpenLogi |
| 平滑滚动 | Mos（CC BY-NC 4.0，非商业许可） | 自己实现，不复制其代码              |

## 非目标

- 不 vendor OpenLogi 的仓库：它的价值在 `openlogi-hid` 设备层，已经作为固定版本的
  依赖在用。整包并进来会带来 GPUI 桌面端、Actions Ring、摄像头、24 种语言，以及
  它的内存问题。
- 不复制 Mos 的代码：CC BY-NC 4.0 与本项目的 MIT 不兼容。平滑滚动按思路重写。
- 不做按键改键、手势、配置档：需要辅助功能 + 事件注入，是另一个量级的产品。

## 形态

两个进程，一个产品：

```
LogiLight.app (AppKit 菜单栏)
        │  Unix socket: ~/Library/Application Support/logilight/control.sock
        ▼
logilight daemon (launchd, Rust)
        ├─ HID++：灯光、DPI、回报率
        └─ 滚动事件 tap（可选，默认关闭）
```

- **守护进程**是唯一常驻、唯一持有 TCC 授权的进程。它现在有「输入监控」；平滑滚动
  需要再加一项「辅助功能」。授权跟自签证书绑定，重建不需要重新授权。
- **窗口**始终是纯客户端，自己不开设备、不装 tap，所以它永远不触发权限弹窗。

## 阶段

### 阶段 1：DPI（本仓库内完成）

- `logilight dpi` 读取当前值、支持范围和步进；`logilight dpi 1600` 写入。
- `status` 带上 DPI，窗口加一张「设备」卡片：滑块 + 数值 + 支持范围。
- DPI 存在鼠标里，不写进 `config.toml`：配置只描述「我们想要什么」，DPI 是设备的
  状态，读设备为准，避免两份真相。
- 验证：G502 HERO 实测（`0x2201`，范围 100–25600，步进 50）；G102 到货后用
  `logilight doctor` 确认。

### 阶段 2：平滑滚动（本仓库内完成，默认关闭）

- 守护进程注册一个 `CGEventTap`，只处理鼠标滚轮事件（触控板惯性事件原样放行）。
- 拦截到的滚动不直接丢弃，而是进入插值队列，由 120 Hz 的定时器按缓动曲线分帧
  重发，形成平滑滚动。
- 安全规则（这是 2026-11-26 滚轮卡死的教训）：
  1. **默认关闭**，配置里 `[scroll] enabled = false`；关着的时候根本不装 tap。
  2. 收到 `kCGEventTapDisabledByTimeout` / `ByUserInput` 立即重新启用并记日志。
  3. 自己重发的事件打上标记，回调里直接放行，避免自激循环。
  4. 定时器连续失败时自动停用平滑，退回系统原始滚动。
  5. `logilight smooth off` 和窗口里的开关是即时熔断。
- 验证：纯逻辑（插值、缓动、分帧）单测；合成滚动事件跑通「拦截 → 重发」链路；
  真机手感需要人来试，所以默认关闭，由使用者主动开启。

### 阶段 3：收尾

- 卸载 OpenLogi（DPI 和灯光都由本产品接管）。
- 平滑滚动稳定后卸载 Mos。
- 两个第三方程序都去掉之后，系统里只剩一个滚动 tap。

## 不做的事

- 不引入网络、不做遥测、不加后台轮询（DPI 只在窗口打开或命令触发时读）。
- 不为新功能新增进程。
